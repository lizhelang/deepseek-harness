# Agent Note: 对话持有的生产工作流

Status: implemented

[English](2026-10-08-conversation-owned-production-workflow.md) | 中文

## 问题

普通 AEA 对话可以执行真实工具，而单独启动的生产流程仍为空。仅复制对话进度的监控不能让流程编辑控制执行。启动第二个调度器又会重复持有同一个案件，可能把原生工作分派两次。四个视图需要共同的运行身份和真实准入规则，而非另一个执行器。

## 决策

可信对话提供方把符合条件的父对话调用绑定到一次生产运行。Production Studio 围绕同一个 ToolRuntime 调用串行化流程编辑、准入与结算，父对话仍是唯一的 agent（智能体）执行器。只读几何、制造、文件与目标检查根据真实回执推进。普通调度器跳过对话式运行，并为未绑定的调度式运行保留现有子 agent 行为。

绑定 AEA 的执行遵循现有 Host 的有界优化与制造动作，不改变冻结设置和预算。它不继承默认调度式流程的基线限定 `user_requested` 完成捷径。提供方绑定真实用户输入与案件身份，模型文字不能选择其他源或认证交付。

### 未来编辑与继续执行

[固定的生产对话流程](2026-10-22-fixed-production-conversation-graph.zh.md)取代了本节及上文所述的流程编辑、人工节点和未绑定调度器；使用过这些功能的已保存运行保持只读。本说明中的绑定、单执行器、继续执行、检查点和恢复规则仍然有效。

流程保存比较预期流程版本。受支持的未来提示词、工具列表和接线改变同一次运行。已准入节点的执行设置和出线保持不可修改，标签和画布位置不改变执行。人工节点批准后保留稳定的准入记录，不随后续阶段变化而消失，因此阶段变化不能让已准入设置或已消费接线重新变为可编辑。必需证据检查不能弱化，执行与重试预算不能增加。提示词装配阶段的工具过滤，在实际准入阶段也有对应限制。

当前对话适配器只识别 `baseline`、`manufacture`、`repair` 三个 agent ID。它拒绝并行接线、自定义 agent ID、按节点覆盖提供方或模型、程序节点，以及只读 AEA 证据检查以外的自动操作。人工节点可以暂停准入，但不提供另一个执行器。

显式恢复和人工回答解除限制，并可能推进只读检查。只有运行处于活跃状态、有可执行 agent 节点且没有人工等待、未知结果或在途调用时，才继续同一个父对话。符合条件的继续执行统一使用 `steer`，包括前一次取消尚在收尾时，不根据驱动器的暂时状态选择 `inject`。已记录上下文使用现有来源类型 `user-approval` 表示显式 UI 批准，不是普通 `user` 消息，并保留同一次运行、源绑定、已消费接线与剩余执行预算。它不授予重放已结算或未知调用的权限。保存流程、重新连接与状态读取从不唤醒工作。

### 当前状态与不可改写的历史

生产存储域持有按 Session ID 保存的当前状态，任务监控与流程编辑消费其已提交快照。对话运行的版本变化把完整运行 `production/checkpoint` 事件追加到同一个 Session，对话与轨迹按原日志序号渲染每个事件，不会把旧卡片替换成最新运行状态。检查点仅写入日志，并带有 `ignorable: true`，允许同格式但没有这个可选事件声明的读取器跳过它。它既不增加模型上下文，也不承诺结构格式的降级兼容性。

可选 `pendingCheckpoints` 待发队列与变化后的运行状态在同一条生产领域记录中提交，因此 Session 追加失败后，检查点在重启时仍可取得。仅 Host 使用的 `productionCheckpoints` Session 投影把已接受检查点折叠为每次运行的最大版本，其游标只证明已接受，不证明落盘。发布先查该投影，跳过已接受的运行／版本，再等待 `ctx.sessions.flush(session)` 并确认返回 `true`，然后才能确认并清除已发布待发条目。即使依据游标跳过了追加，也必须刷新。返回 `false` 或抛出错误时，待发元数据仍保留供重试；确认写入失败也会保留条目，不添加重复历史。这仅恢复元数据，绝不重新分派检查点所代表的工具或原生操作。

领域状态／待发队列提交和 Session 持久化是分开的写入。检查点追加或持久性刷新失败属于明确可见的历史发布错误，不是未知原生结果，新准入等待待发布元数据完成持久化发布。领域写入失败的已知回执连同调用身份仍保留在进程内，发布重试从不重新分派该操作。持续领域写入故障不具备持久性，结算提交前进程突然丢失仍可能留下持久化记录中的未决调用。

可选 Session 事件的 `ignorable` 标记允许同版本但没有该事件声明的读取器跳过它，不保证新的生产领域持久化字段兼容：旧严格领域读取器可能拒绝这些字段，即使当前读取器允许它们缺省。回退使用匹配的更新前应用与数据备份，不是让旧应用解析新的生产状态。

### 暂停与未决结果

暂停阻止下一次对话操作开始，不丢弃已准入调用的结果。生命周期关闭会等待已准入父对话调用结算后再关闭状态。停在两次已知回执之间的对话节点进入暂停状态，可以恢复而不重放。只有没有已知结算的调用变成未知。已知拒绝检查仍属于失败，人工回答和恢复都不能认证未知操作。

全局原生租约独立于流程资源设置。可信分派标记区分进入原生分派前的拒绝，以及已经分派但结果未决的操作。未知原生工作在取得精确可信的完成证据前保持隔离，目前没有通用核对提供方提供该证据。

## 考虑过的替代方案

**把普通对话镜像到独立任务板。** 镜像可以显示活动，却使未来节点编辑与执行脱节，无法满足流程控制后续对话步骤的要求。

**为绑定对话再启动一个子 agent 调度器。** 现有调度执行器保留给显式的未绑定运行。把它添加到已在执行的父对话，会让同一原生工作具有两个持有者和另一份模型历史，而非同一次执行的四个视图。

**改写过去事件，或始终在旧卡片中渲染当前运行。** 两种方式都会使历史对话位置显示的内容随后续编辑而改变。按序号区分的完整运行检查点保留该位置当时的流程版本与状态，不改写 Session 历史。

## 影响

一个父执行器让流程编辑真正生效，同时保留源输入、Host 检查与原生独占性。它也把对话流程限制在适配器完成规则和父对话当前模型之内。UI 不能承诺此模式下的任意并行、程序或自定义模型执行。普通调度式运行仍是独立显式模式，不是隐藏回退。

四个视图在不同时间维度描述同一次运行：当前控制追踪领域状态，历史视图保留已提交的 Session 检查点。发布错误可能暂时使这些观察不同步，并保持明确可见。恢复优先保留已知回执、阻止未决变更，而非自动重放或悄悄宣告完成。

## 测试

[对话回归](../../../../packages/workflow/production-studio/tests/conversation.spec.ts)使用真实父对话驱动器与确定性工具 fixture（测试前置数据），覆盖直接调用工具拒绝、使用 `user-approval` 显式继续空闲父对话、检查点发布失败，以及已知回执的生命周期结算。它们也验证未决调用会拒绝恢复与第二次分派。[原生租约回归](../../../../packages/workflow/production-studio/tests/native-lease.spec.ts)覆盖原生租约与隔离。这些无密钥测试验证软件行为，不验证真实 Rhino 几何、实物回折或车间验收。原生与已安装应用的验证仍由集成负责人承担。
