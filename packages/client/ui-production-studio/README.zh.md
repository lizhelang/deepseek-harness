# @deepseek-ai/dsh-client-ui-production-studio

[English](README.md) | 中文

## 概述

这个浏览器插件在对话视图中加入**任务监控**与**流程编辑**，并在现有输入框上方加入可展开的监控条。对话、轨迹、Goal、Todo、附件粘贴与模型选择仍由各自原有组件负责。三个 Studio 界面共享同一份真实的 `productionStudio` Remote 快照；安装后的应用没有演示任务或模拟进度。

## 使用本包

任务监控先显示受阻或结果未知的任务，再显示人工决策、等待依赖、执行中、暂停和默认折叠的已交付任务。每个工件只有一行，展开后显示 Agent 分支，再展开显示尝试记录与观察证据。分支暂停、恢复、人工补信息与未知结果核对携带任务修订号，调用真实 Host 方法。

已完成交付直接展示验证后的文件，包括绝对路径、字节数、SHA-256 和复制路径操作。这些条目只读取已完成交付分支的最新内部 `production_aea_evidence` 回执，不读取模型输出。几何、制造、保存文件和目标验证与尚未验证的工厂验收及实物回折分别标注。恢复只适用于暂停任务；受阻任务展示诊断，需要补足能力或使用新的流程／任务。

流程编辑支持拖动节点、点击或拖动端口连线、移除连线、添加 Agent／检查门禁／人工门禁、画布平移缩放、端口类型检查与显式节点设置。节点属性包括职责提示、模型路由、工具白名单、原生资源串行、尝试上限、工具参数、证据字段、JSON 期望值、文件路径以及执行前后断点。四个必需的证据生产者和检查条件只读，附加门禁仍可配置。交付必需的证据检查路径不能绕过；Host 会重新校验每份提交的草稿。

保存只改变流程草稿，已启动的任务保留启动时的独立流程副本。未提交的流程、目标、JSON 输入或人工回复都是界面草稿，不会被任务流更新替换。启动需要明确操作、具体目标和任务输入，可能执行工具或消耗模型 token。查看监控不会启动历史工作。

启动表单明确交付类型，并提供成型件数、焊接次数、折弯次数和制造评分的可选上限。数值留空表示该项不设限制，文字说明不会替代这些客观检查。表单说明有限试验范围：先尝试原生方案，达到所填目标即交付；只有失败或未达目标才需要修复和必要优化，不承诺耗尽搜索或全局最优。启动要求用户确认显示的条件与范围完整表达交付要求；修改说明、条件或输入会取消这个确认。提交的目标记录原样的说明文字。

<a id="understand-the-implementation"></a>
## 理解实现

`src/client/index.ts` 负责 Cordis effect 和 slot 注入。`production-source.ts` 在追踪真实 Host 状态时保留会话引用，最后一个观察者离开后关闭流，连接重置后重新订阅，并阻止晚到的读取覆盖更新的修订。`stores.ts` 只负责未提交的界面状态。组件通过 props 接收数据与回调，不访问 Cordis context。产品文案属于带类型检查的中英文字典，CSS 使用现有语义主题 token。

没有发布 `./invariant` 附件：本包只负责展示和明确的用户操作，没有一份可能独立偏离执行状态的第二观察。生产执行证据与流程校验由 `dsh-production-studio` 负责。

<a id="model-experience"></a>
## 模型体验

### 明确启动任务与人工回复

#### 模型所见

这个界面不提供提示章节或工具 schema。明确启动调用 `productionStudio.start`，人工回复操作调用 `productionStudio.answer`。它们将输入目标、JSON 数据和回复转交给 [Production Studio](../../workflow/production-studio/README.zh.md)，由它负责接纳及模型可见性。

#### Token 影响

查看、编辑流程和监控都不会增加模型 token。明确启动的流程可能通过生产运行时调用子 Agent。

#### KV Cache 影响

界面不会读取或修改请求历史。生产运行时负责独立的子请求与接纳后的回复上下文。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与待完成工作

- **能力绑定：** 本界面不提供 AEA／Rhino 能力实现。任务快照列出当前 Host 的工具、子 Agent 和文件系统能力。能力不可用或客观证据未绑定时，会显示明确诊断。
- **执行中的流程版本：** 流程修改适用于未来任务，明确不支持改变执行中任务的流程。
