# @deepseek-ai/dsh-production-studio

[English](README.md) | 中文

## 概述

Production Studio 让已绑定的 AEA 对话、案件面板、运行策略和轨迹共用同一次固定流程的运行。对话执行每个 agent（智能体）步骤；服务准入每次实际工具调用并执行只读交付检查。交付仍要求通过几何、制造选型、文件字节与哈希，以及已记录交付条件的检查。

## 使用此包

此服务依赖 agent、工具、文件系统和 storage-domain。可信对话提供方把直接的 AEA 调用绑定到固定流程。没有提供方时，服务只读取和核对已有运行。此包不增加模型可调用的工具 schema。

```yaml
- name: '@deepseek-ai/dsh-production-studio'
```

部署默认值为 80 次执行、256 KiB 保留证据、每个文件最多读取 4 MiB、400 条历史和每个会话保留 20 次运行。对话流程始终只有一个执行器。较大图纸需要配置 `maxFileBytes`；[配置目录](../../../docs/config-catalog.zh.md)负责记录可接受的部署字段。

### 绑定的 AEA 对话

通过现有对话发送模型处理请求。AEA 提供方把首次符合条件的 `create_case` 调用绑定到真实用户目标与源输入。同一个父对话执行 agent 节点，流程仅准入并记录每次实际工具调用一次。流程是固定的：基线、几何检查、制造、制造检查、文件检查、目标检查、交付，检查失败后进入修复。每项检查在其 certification 阶段读取 `production_aea_evidence`。客户端选择的运行策略作为普通对话消息到达模型，不改变流程、预算或检查。

`pause`、`resume`、`reconcile` 要求运行 ID 与当前版本。对话暂停阻止下一次操作准入；已分派的操作仍可返回已知结果。停在两次已知回执之间的节点为暂停状态，可以恢复。真正未决的调用为未知状态：恢复不授予重放权限。已知检查失败属于阻塞，不是未知执行结果。外部修复后，显式暂停/恢复只可重新开放最后一个已结清的失败 agent 节点，前提是没有原生执行占用租约、没有节点存在未决调用，且执行预算尚未耗尽；原结果、调用身份和已消费计数保持。不满足这些条件的阻塞任务暂停请求会直接拒绝，不改变运行、节点或修订号。

显式恢复解除工作流限制，并可能推进只读检查。运行处于活跃状态、有可执行的 agent 节点且没有未知结果或在途调用时，服务继续同一个父对话。符合条件的继续执行统一使用 `steer`，包括前一次取消尚在收尾时；它不根据驱动器的暂时状态选择 `inject`。继续执行保留源绑定、已消费接线与运行剩余预算，不启动另一次生产运行，也不重放已结算调用。读取状态和重新连接从不唤醒空闲驱动器。

对话适配器保留 AEA Host 的有界搜索、必需制造评估、比较和修复动作，沿用原冻结设置与预算。它不强加基线限定的 `user_requested` 捷径，不把搜索分数当成制造成本，也不证明全局最优。

可信提供方在 Host 确认没有可执行的后续动作时，可以返回 `outlet: 'failure', terminal: true`。服务保留已知回执并阻塞当前节点，不转到修复。普通失败仍沿原修复接线；未决回执仍优先标为未知。仅在工具回执数据中写入 terminal 标志不会改变执行。

提供方还可以返回 `caseView`，即 Host 回执的显示投影（阶段、预算、候选结果、结束条件、下一步和选定交付文件）。服务记录结算时间并保存为 `run.case`，替换之前的视图；不含 `caseView` 的观察保留原视图。门禁、证书、路由与重放判断都不读取该视图。

已知的终止失败保留节点不可变的传入状态，使显式恢复能够将后续修复回执与原失败状态比较。普通路由结果仍消费该传入状态；恢复不会重置证据、尝试次数或预算。

### 已退役的运行

早期版本还支持带子 agent 的独立调度式运行、流程编辑和人工决策节点。这些已保存的运行仍可读取和核对，但 `pause` 与 `resume` 会拒绝调度式运行，以及流程与固定流程不同的对话运行。新工作请在新对话中开始。

<a id="evidence-and-recovery"></a>
### 证据与恢复

必需路径在交付前检查几何、制造、保存文件和已记录目标。Host 内部的 `production_aea_evidence` 读取真实 AEA 账本和报告，验证身份与报告哈希，并从二进制字节计算两个选中模型的哈希。几何检查读取账本 `baselineCandidateId`（最近一次已验证的基线或修复候选）的搜索报告，之后的探索性改进尝试不会替代它。制造选型必须把真实成功工具回执与账本绑定。模型文字和单独路径不能认证交付。

可信插件通过 `registerNativeBoundaryProvider(toolNames, { readOnlyToolNames })` 声明精确的原生工具名，声明由 effect 管理并按引用计数。这些调用共用持久化原生独占租约。精确的原生声明优先于冲突的只读声明。明确声明的只读工具（例如 `rhino_api_lookup`）不占用租约；未声明的旧 AEA 和 `rhino_*` 名称仍按原生操作保守处理。可信原生提供方在开始原生工作前记录分派。分派前拒绝属于已知失败，已分派调用出错或原生回执未决则隔离后续原生工作。`reconcile` 只接受 Session ID 和带版本比较的运行／节点引用，调用方不能提供自己的安全标记或回执。

可信插件通过 effect 注册 `registerNativeReconciliationProvider({ id, toolNames, reconcile })`，可选的 `appliesTo(sessionId)` 将其限制在所属预设的 Session。每次选择，包括等待 Host 读取之后，都要求恰好匹配一个提供方。DSH 提供原始 Session 调用／结果事件、参数原文的 SHA-256、运行、任务与原生租约。提供方只读权威 Host 账本，不执行工具，并返回完全一致的 Session／调用／工具／哈希身份、结果（`rejected_before_native`、`completed` 或 `unknown`）、回执和证据。事件缺失、身份不一致、多个提供方匹配以及陈旧引用均保留隔离。执行完成不授予工程认证。手动核对暂停原节点；显式恢复保留已消耗的尝试次数与执行次数。新记录的错误若具有经过核验的原生执行前拒绝回执，会在下次提示词装配前自动结清，让同一对话从该错误继续，不重放调用。

经过认证的控制端可对空闲、已暂停、收件箱为空且没有原生租约的对话传入 `resume(sessionId, ref, { requestId, text })`。UUID、文本和生成的消息 ID 先写入检查点，再仅投递一次继续执行消息；其来源为带有该 `rpcId` 的 `user-approval`。陈旧引用或重复 UUID 均拒绝重发，重启或收件箱投递结果不确定时也一样。文本及完整消息受配置的证据字节上限约束。返回的任务证据标识已准入请求，Session 历史标识其最终消费。普通恢复保留默认继续执行文本。

结清记录先持久化到原生租约，再附到原任务并持久化检查点，最后才释放该租约。中间写入失败继续阻止新操作准入。中断或重启后，重试核对会按已记录的身份和证据完成原结清，不再次查询 Host 或分派工具。没有结清元数据的旧租约仍可读取并保持未知，元数据缺失从不表示成功。

较大的普通工具诊断可保存为 `data.productionEvidenceReference`，避免重复内联 JSON。完整观察记录先写入存储域的 `evidence` 表，并绑定所属 Session、SHA-256、UTF-8 字节数与观察元数据。`readEvidence(sessionId, observation)` 将这些精确字节恢复为 JSON，引用缺失、被修改或属于其他会话时拒绝读取。核对与具名继续操作也会先归档旧的超大诊断记录，再执行原有的完整保留字节上限。客观 `production_aea_evidence`、结清和文件证据仍完整内联。客观检查前先还原引用，继续执行原始完整证据字节上限与认证条件；归档不能让超限证明通过。归档内容随存储域保留，目前不自动回收。

结算写入失败不会把已返回的结果变成未知。服务在进程内保留已知回执和调用身份，在结算提交前阻止新操作准入，并重试发布而非重新分派工具。持续的领域写入故障不具备持久性。状态与待发布历史检查点一同提交后，追加或持久性刷新失败会留下可恢复的元数据待发队列，并明确显示发布错误。新操作准入等待该队列完成持久化发布，重试或重启绝不会通过分派原生工作来恢复历史。

## 理解实现

<details>
<summary>实现内部细节——点击展开</summary>

服务串行化准入和结算，父对话持有每次绑定工具调用。只读流程检查根据真实回执推进。[服务](src/index.ts)负责生命周期结算与发布，[领域模块](src/domain.ts)负责已保存状态校验与固定对话流程。

`production_studio` 存储域持有按 Session ID 保存的当前执行状态，以及独立全局原生租约表。每次对话运行变化与可选的 `pendingCheckpoints` 待发队列在同一次领域状态写入中提交。随后发布过程把带有 `ignorable: true` 的完整运行 `production/checkpoint` 事件追加到同一个 Session。对话和轨迹在原日志序号处渲染每个历史事件，案件面板追踪当前状态。当前状态变化不会改写历史检查点卡片，fork 也不继承活跃运行权限。

仅 Host 使用的 Session 投影 `productionCheckpoints` 记录每次运行已接受的最大检查点版本。其游标只证明 Session 已接受追加，不证明事件已经落盘。发布和重启恢复在追加待发条目前先查该投影，已经接受的运行／版本不会再次追加。在确认并清除任何已发布待发条目前，发布过程必须等待 `ctx.sessions.flush(session)` 并确认返回 `true`，即使依据游标跳过了追加也一样。返回 `false` 或抛出错误时，待发元数据仍保留供重试。待发队列的确认写入失败也会保留条目，不添加重复历史。恢复只重新发布元数据，不重放对应工具或原生操作。领域状态／待发队列提交和 Session 持久化仍是分开的写入，不是同一个原子事务，发布错误会明确显示。

原生调用投影对所有已提交的工具调用和结果建立索引，不依赖当前激活的提供方。Session 回放后注册新的原生操作仍保留其原始调用身份；重复身份仍具有歧义，不能授权核对。

停止时，服务等待已准入父对话调用结算后再关闭状态。两次操作之间的已知对话回执仍可恢复，只有未决调用变成未知。恢复过程不会自动分派任何一种状态。[架构决策](../../../.agents/notes/implemented/architecture/2026-10-08-conversation-owned-production-workflow.zh.md)记录了为什么四个视图共用一个执行器。

</details>

## Model Experience

### 绑定对话的步骤

#### What the model sees

提示词装配把活跃运行身份、流程版本、阶段和当前 agent 节点提示词添加到父对话。装配按该节点的允许列表过滤已注册工具，ToolRuntime 准入也会对直接调用执行相同限制。工作流检查点仅写入日志，不添加模型消息。符合条件的显式恢复添加已记录的继续执行上下文，使用现有来源类型 `user-approval`，归属于显式 UI 批准，而非来源类型为 `user` 的普通人工消息。上下文标识同一次运行，要求保留源绑定、已消费接线与剩余执行预算。末尾指令为 `Never repeat a settled invocation or start a second run.`

#### Token effect

父对话承担现有对话请求成本，以及当前工作流指令和已准入继续执行上下文的成本。显式控制可以唤醒空闲父对话发起另一次模型请求，但不重置运行已消耗的执行预算。监控与检查点渲染不增加模型 token。流程预算限制准入的流程工作，而非模型 token 用量。

#### KV Cache effect

正常父对话请求与系统提示词策略决定复用。继续执行上下文进入已记录的用户消息历史，不改写较早的对话消息；节点变化会改变工作流提示词和工具列表，可能影响下次请求的缓存复用。

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>

对话工作流有以下限制：

- **未知操作核对** — 原生提供方必须把权威证据绑定到精确原调用。未注册的工具、歧义或缺失的 Session 事件、不受支持的历史 Host 记录仍保持未知。
- **固定流程** — agent ID 限于 `baseline`、`manufacture`、`repair`，没有并行分支、按节点覆盖模型或可编辑的检查。搜索深度和制造范围通过对话在 Host 冻结上限内提出。
- **继续执行的条件** — 显式恢复只唤醒有可执行 agent 节点、且没有未知结果或在途调用的活跃对话运行。它本身不解决已阻塞或未知工作。
- **能力缺失与存储** — 缺少真实绑定时不能模拟成功。二进制读取受文件大小限制。此处同版本兼容性仅指可选 Session 仅日志事件的 `ignorable` 标记。不保证旧 DSH 的严格读取器能够解析新的生产领域字段，即使新字段为可选也是如此。回退需要匹配的更新前应用与数据备份，不代表旧应用能够打开新的领域状态。领域状态／待发队列提交不与 Session 持久化构成原子事务。
- **验收范围** — 软件检查和文件哈希证明本流程的交付条件，不等于实物加工验收、车间验收或专家认可新工件。
